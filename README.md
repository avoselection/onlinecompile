# onlinecompile

Локальный онлайн-редактор Python-кода для учебной сессии: преподаватель создаёт комнату, студенты подключаются через браузер, изменения синхронизируются по WebSocket, код запускается на сервере в отдельном подпроцессе.


## Быстрый запуск

```bash
poetry install
poetry run python server.py
```

После запуска откройте один из адресов, которые сервер выведет в консоль. По умолчанию это `http://127.0.0.1:8000` (для локального доступа только Вам).


## Доступ преподавателя

Если рядом с `server.py` нет файла `config.json`, используется временная учётная запись:

- логин: `HOST`
- пароль: `Example1`

Для нормальной эксплуатации создайте (или скачайте) `config.json` и замените пароль. Чтобы получить bcrypt-хеш:

```bash
poetry run python server.py --hash-password "новый пароль"
```

Или сначала запустите `generate_bcrypt_hash.py` перед запуском сервера и вставьте значения в `config.json`


### Основные возможности

- создание и восстановление комнаты преподавателем;
- подключение студентов к существующей комнате;
- синхронизация документа через WebSocket;
- выдача и отзыв права редактирования студенту;
- ограничение редактирования диапазоном строк;
- запуск Python-кода с тайм-аутом в подпроцессе;
- принудительная остановка запуска, включая бесконечные циклы;
- проверка синтаксиса через AST;
- импорт, создание, скачивание текущего `.py`-файла и скачивание архива файлов комнаты;
- сохранение общего файла преподавателем и личных копий студентами;
- cooldown личного сохранения студента: 1–5 минут, по умолчанию 1 минута;
- HTML/CSV/JSON-отчёты по blame и выдачам доступа;
- локальная светлая/тёмная тема.


### Защитный режим запуска кода

Перед запуском код проходит быструю проверку размера, глубины вложенности скобок и AST-обход. Учебный runner блокирует опасные импорты и вызовы вроде `os`, `subprocess`, `open()`, `eval()` и `input()`, запускает Python в изолированном режиме `-I -S`, закрывает stdin, ограничивает CPU/память/размер файлов и очищает окружение процесса.

Это снижает риск случайных и простых вредных действий, но не является полноценной песочницей. Для публичного сервера или недоверенного кода всё равно нужен внешний sandbox: Docker/rootless-контейнеры, gVisor, nsjail, firejail или отдельная одноразовая VM.


## Настройки через переменные окружения

- `ONLINECOMPILE_STUDENT_SAVE_COOLDOWN_SECONDS` — задержка между личными сохранениями студента. Значение автоматически ограничивается диапазоном от 60 до 300 секунд.
- `ONLINECOMPILE_RELOAD=1` — запуск `uvicorn` с autoreload при локальной разработке.


### Структура проекта

```text
server.py              # Основной сервер работоспособности отчетов и т.д.
static/
    index.html         # интерфейс
    app.js             # клиентская логика
    styles.css         # стили
    vendor/monaco      # локальный редактор Monaco
config.json            # конфигурации преподавателей
room_data/             # создаётся автоматически, данные созданных комнат
```


## ВАЖНО

1. Данная реализация отлично подходит для учебных сессий преподавания программированию на языке Питон или проверки компетенций рекрутеров, а не промышленных sandbox-платформенных задач, нужно корректировать под ваши нужны в таком случае.
2. Встроенные лимиты запуска кода помогают, но не заменяют полноценную изоляцию.
