# onlinecompile

Локальный онлайн-редактор Python-кода для учебной сессии: преподаватель создаёт комнату, студенты подключаются через браузер, изменения синхронизируются по WebSocket, код запускается на сервере в отдельном подпроцессе.


## Быстрый запуск

```bash
poetry install
poetry run python server.py
```

После запуска откройте один из адресов, которые сервер выведет в консоль. По умолчанию это `http://127.0.0.1:8000` (для локального доступа только Вам).


## Доступ преподавателя

Если рядом с `server.py` нет файла `config.json`, используется временная учётная запись:

- логин: `HOST`
- пароль: `Example1`

Для нормальной эксплуатации создайте (или скачайте) `config.json` и замените пароль. Чтобы получить bcrypt-хеш:

```bash
poetry run python server.py --hash-password "новый пароль"
```

Или сначала запустите `generate_bcrypt_hash.py` перед запуском сервера и вставьте значения в `config.json`


### Основные возможности

- создание и восстановление комнаты преподавателем;
- подключение студентов к существующей комнате;
- синхронизация документа через WebSocket;
- выдача и отзыв права редактирования студенту;
- ограничение редактирования диапазоном строк;
- запуск Python-кода с тайм-аутом в подпроцессе;
- принудительная остановка запуска, включая бесконечные циклы;
- проверка синтаксиса через AST;
- импорт, создание, скачивание текущего `.py`-файла и скачивание архива файлов комнаты;
- сохранение общего файла преподавателем и личных копий студентами;
- cooldown личного сохранения студента: 1–5 минут, по умолчанию 1 минута;
- HTML/CSV/JSON-отчёты по blame и выдачам доступа;
- локальная светлая/тёмная тема.


### Защитный режим запуска кода

Перед запуском код проходит быструю проверку размера, глубины вложенности скобок и AST-обход. Учебный runner блокирует опасные импорты и вызовы вроде `os`, `subprocess`, `open()`, `eval()` и `input()`, запускает Python в изолированном режиме `-I -S`, закрывает stdin, ограничивает CPU/память/размер файлов и очищает окружение процесса.

Это снижает риск случайных и простых вредных действий, но не является полноценной песочницей. Для публичного сервера или недоверенного кода всё равно нужен внешний sandbox: Docker/rootless-контейнеры, gVisor, nsjail, firejail или отдельная одноразовая VM.


## Настройки через переменные окружения

- `ONLINECOMPILE_STUDENT_SAVE_COOLDOWN_SECONDS` — задержка между личными сохранениями студента. Значение автоматически ограничивается диапазоном от 60 до 300 секунд.
- `ONLINECOMPILE_RELOAD=1` — запуск `uvicorn` с autoreload при локальной разработке.


### Структура проекта

```text
server.py                  # FastAPI-сервер: комнаты, синхронизация, запуск кода, отчёты
scripts/
    vendor_xterm.py        # скачать xterm.js для офлайн-работы терминала
static/
    index.html             # интерфейс
    app.js                 # клиентская логика
    styles.css             # стили
    vendor/monaco/         # локальный редактор Monaco (офлайн)
    vendor/xterm/          # локальная копия xterm.js (опц., см. scripts/vendor_xterm.py)
tests/                     # pytest
config.example.json        # шаблон конфигурации преподавателей (скопируйте в config.json)
config.json                # ваши учётные данные (gitignored; если нет — используется HOST/Example1)
room_data/                 # создаётся автоматически: файлы комнат, отчёты, личные копии
```


## ВАЖНО

1. Данная реализация отлично подходит для учебных сессий преподавания программированию на языке Питон или проверки компетенций рекрутеров, а не промышленных sandbox-платформенных задач, нужно корректировать под ваши нужны в таком случае.
2. Встроенные лимиты запуска кода помогают, но не заменяют полноценную изоляцию.

## Что нового в этой версии (v14)

### Терминал работает офлайн (важно для учебных классов без интернета)

Терминал на xterm.js загружается по трёхуровневой схеме:

1. **Локальная копия** `static/vendor/xterm/` — полностью офлайн.
2. **CDN jsDelivr** — если локальной копии нет, но есть интернет.
3. **Встроенный `<pre>`-терминал** — если недоступны оба варианта, вывод всё равно отображается и не теряется.

Чтобы сделать терминал полностью офлайн, один раз выполните на машине с интернетом:

```bash
python scripts/vendor_xterm.py
```

Скрипт скачает `xterm.min.js`, `xterm.min.css` и `addon-fit.min.js` в `static/vendor/xterm/`. После этого учебный класс может быть полностью изолирован от сети — и редактор (Monaco), и терминал (xterm) обслуживаются локально.

### Заголовки безопасности

Сервер добавляет базовые заголовки на все ответы: `X-Content-Type-Options: nosniff`, `X-Frame-Options: SAMEORIGIN`, `Referrer-Policy: same-origin`, `Permissions-Policy` (камера/микрофон/геолокация выключены). Автодокументация FastAPI (`/docs`, `/redoc`, `/openapi.json`) отключена, чтобы не раскрывать схему API.

### Улучшения интерфейса

- Кнопка «Выйти» из комнаты в шапке.
- Показ/скрытие пароля на экране входа.
- Счётчик участников рядом с заголовком списка.
- Метка «вы» у себя в списке участников и подсветка активного редактора.
- Кнопка «Очистить» терминал теперь доступна и студенту (раньше пропадала вместе с кнопками запуска).
- Высота терминала запоминается между сессиями (drag-resize сохраняется в localStorage).
- Поддержка `prefers-reduced-motion`, видимый фокус для доступности с клавиатуры, корректный `100dvh` на мобильных.

## Развёртывание в продакшене (школы / компании)

Для эксплуатации за пределами «локально у преподавателя»:

1. **HTTPS** — поставьте сервер за обратный прокси (nginx/Caddy) с TLS. Клиент сам переключится на `wss://`.
2. **Один воркер** — состояние комнат хранится в памяти процесса. Запускайте с `--workers 1` (по умолчанию). Для горизонтального масштабирования потребуется вынести состояние во внешнее хранилище (Redis) — это отдельная доработка.
3. **Реальная песочница** — для недоверенного кода добавьте Docker/gVisor/nsjail поверх встроенных лимитов (см. «Защитный режим запуска кода»).
4. **config.json** — обязательно создайте свой с bcrypt-хешем; не коммитьте его (он в `.gitignore`).
5. **Бэкап `room_data/`** — там хранятся файлы комнат, отчёты и личные копии студентов.
